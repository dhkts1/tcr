Run Claude Code and Codex across multiple accounts

tcr is a local proxy for Claude Code and Codex. It sends each request to the account with quota left, and keeps every conversation on the account that already holds its prompt cache. TcrBar, a menu-bar app for macOS, shows every account.

How it works

Log in each account once, then start Claude Code through tcr

Every request goes through the proxy on your own machine, which picks an account from the pool. Claude Code keeps one setup and never needs to know there is more than one account.

  1. Add your accounts

    Sign in through the browser, once per account. Already logged in to Claude Code? The first run imports that login, and Claude Code asks you to sign in once more.

    $ tcr login
$ tcr login --codex  # for codex

  2. Start the proxy

    It opens a live terminal dashboard. On a Mac, TcrBar can run it for you from the menu bar instead.

    $ tcr

  3. Run Claude Code through it

    tcr run starts Claude Code pointed at the proxy. tcr setup shell makes a plain claude do the same.

    $ tcr run
$ tcr run --codex    # codex

Prompt cache

Switch accounts without losing the prompt cache

Anthropic keeps the prompt cache per account. A conversation that moves to another account arrives cold and writes its whole cached prefix again. So tcr keeps each conversation on one account, and moves it only when that account cannot serve the request.

Measured: what each proxy costs

On a 2 MB request, tcr adds 4 ms. The other proxies add 44 to 170 ms and use 4 to 42 times the CPU. Long Claude Code conversations send requests of several megabytes, and every one of them pays this.

Where they tie. With a 10 KB request every proxy adds under 4 ms at the median, and tcr and CLIProxyAPI start up in about the same time. claude-swap, cux and cc-account-switcher add nothing per request because they are not in the request path; their cost comes at each switch, when the conversation's cached prefix is written again.

How it was measured. 2026-10-20, on one 14-core Apple silicon Mac: tcr 1.2.14, teamclaude 1.1.25, CLIProxyAPI 8.0.35 (the proxy Quotio runs) and ccs 8.10.0 with its account pool, each against the same local stand-in for Anthropic's API, 2,400 streamed requests per tool and size, every response checked. The machine was busy (load average 136 to 232), so read the latency as an order rather than an exact figure; CPU agreed within 4% across two passes and memory within about 15%. CLIProxyAPI ran with API keys aimed at the stand-in, because its Claude logins cannot be pointed at another host.

Another tool fits better if you need Windows (claude-swap, ccs, cux), want Gemini or other providers behind the same tool (teamclaude, ccs, Quotio), want no proxy in the request path (claude-swap, cux, cc-account-switcher), or need an open-source license for commercial use (every other row). Moving from claude-swap, Quotio, ccs or CLIProxyAPI? tcr import lists the logins they hold.

FAQ

Questions people ask first

How do I use Claude Code with more than one Claude account?

Install tcr, run tcr login once for each account, start the proxy with tcr (or let TcrBar run it), and launch Claude Code with tcr run. Every request then goes through the proxy, which picks an account from the pool. If you are already logged in to Claude Code, the first run imports that login, so you only log in to the others. Claude Code then asks you to sign in once more, because a refresh token works only once.

Claude Code has its own answer: CLAUDE_CONFIG_DIR moves its configuration directory, and Anthropic's docs suggest it for running accounts side by side. There you pick the account by picking the directory when you start a session. tcr keeps one Claude Code setup and picks the account for every request instead. It imports Claude Code's default login and does not read CLAUDE_CONFIG_DIR.

Can I use Claude Code with several Max subscriptions?

Yes. Each subscription is one account in the pool: run tcr login once for each. tcr reads every account's five-hour, weekly and per-model weekly windows, and sends each request to one that has quota left.

How do I switch between Codex accounts?

You stop switching by hand. A Codex account is the ChatGPT login codex uses. Sign each one in with tcr login --codex, or import the one codex already has with tcr login --from-codex, then start codex with tcr run --codex. Codex accounts are picked, refreshed and checked for quota the same way Claude accounts are, and a Codex request is only ever served by a Codex account.

Does switching accounts lose the prompt cache?

Yes. Anthropic keeps the prompt cache per account, so a conversation that moves arrives cold and writes its whole cached prefix again. A cache write bills at 1.25 times the input price and a cache read at a tenth of it or less, so the first request after a move pays at least 12.5 times as much for that prefix (25 times on Opus 5.5).

That is why tcr keeps each conversation on one account, even past the point where it would send new conversations elsewhere. tcr saves which account each conversation is on, so a restart keeps that for conversations still within the cache lifetime.

How long does the cache stay warm?

Five minutes after its last use, unless the request asks for an hour. From 1.1.19 tcr asks for the one-hour cache on every Claude request, so a conversation you come back to within the hour resumes warm. On a subscription the hour costs the five-hour window what five minutes does (measured 2026-10-06). cacheTtlRewrite turns it off.

What happens when an account runs out?

New conversations skip any account that is close to a limit, on a rate-limit hold, or out of the model window a request needs, and go to the account the quota rules pick next. A conversation already on that account moves once, and pays one cache rebuild.

Does it run on Linux, and with API keys?

The tcr CLI and terminal dashboard run on Linux as static builds for x86_64 and aarch64. TcrBar, the menu-bar app, is macOS only.

Accounts are Claude subscriptions logged in through the browser, or Codex accounts. tcr does not serve Anthropic API keys, and refuses a Codex login made with an API key too.

Is tcr free?

Yes, for noncommercial use. tcr is source-available under the PolyForm Noncommercial License 1.0.0, which is not an open-source license. If you need an open-source license for commercial use, the comparison above lists the tools that have one.

Does tcr send my data anywhere?

No telemetry and no crash reporting. Your config, logs and tokens are files on your own disk. tcr calls Anthropic on your behalf (and OpenAI, for Codex accounts) and GitHub to check for a newer version. If you turn on peers, it also talks to the other Macs you trust, and a Mac that lends you an account sees the requests it serves for you.

Is it safe to run?

tcr holds your account tokens, so get it from the release page or the install script, never a copy repackaged elsewhere. Each CLI archive has a .sha256 file beside it, and TcrBar is signed with a Developer ID certificate and notarized by Apple.

It listens only on 127.0.0.1, but every process and container on the machine can reach that address, and by default nothing asks it for a key. Read the security notes before you run it.
